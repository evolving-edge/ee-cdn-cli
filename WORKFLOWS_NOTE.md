This directory carries its own `.github/workflows/` (`ci.yml`, `publish.yml`), inherited from the standalone `cdn-cli` repo it was imported from (see `git log` around the subtree import commit, or `docs/` for the migration writeup). GitHub Actions only runs workflows that live at the repository root, so as long as `cdn-cli/` stays a subdirectory of this monorepo, neither of those files fires here — they are inert.

Two things to watch for:

- Do not move or copy either file up to the root `.github/workflows/` of this repo. `publish.yml` runs `npm publish` using npm trusted publishing (OIDC), configured on npmjs.com against the org/repo/workflow-filename `evolving-edge/cdn-cli/publish.yml`. If ee-cdn ever assumes that identity (e.g. this repo gets renamed, or the workflow file gets hoisted to root under the same name), the publish could start succeeding here instead of failing safe.
- If `cdn-cli/` is ever split back out to its own repo (subtree push, or a manual export like the one used for `home-assistant-edge-node`), these two workflow files are meant to travel with it and start running for real there. This note (`WORKFLOWS_NOTE.md`) is monorepo-only context and should not go along — it is already excluded from what `npm publish` packs (see `files` in `cdn-cli/package.json`, an allowlist that doesn't include this file), but a future repo-export step should exclude it explicitly too.
